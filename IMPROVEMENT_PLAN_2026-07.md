# Memora — план развития (июль 2026)

> Продолжение [IMPROVEMENT_PLAN.md](IMPROVEMENT_PLAN.md) (итерация июня выполнена) и
> [subject-packs-spec.md](subject-packs-spec.md) (Фаза 1 начата: миграция `subject`, реестр паков).
>
> Зафиксированные решения:
> - **Порядок фаз:** сначала коуч + LLM-генерация упражнений, затем языковые фичи, затем новые предметы.
> - **Масштаб:** семья и знакомые — без биллинга и мультитенантности, фокус на качество обучения.
> - **Математика/физика/история:** французская школьная программа (collège/lycée), контент на французском —
>   предметы одновременно работают как языковое погружение.
> - **LLM:** абстракция «любой OpenAI-совместимый провайдер» (Ollama Cloud остаётся по умолчанию).

## Фаза 0 — фундамент (1–2 недели работы)

### 0.1 Абстракция LLM-провайдера
Сейчас `ai.rs` захардкожен на нативный `/api/chat` Ollama. Ollama сама поддерживает
OpenAI-совместимый `/v1/chat/completions`, поэтому правильный ход — **один клиент под
OpenAI-формат**, который покрывает Ollama Cloud, локальный Ollama, OpenRouter, Groq,
Together, DeepSeek и сам OpenAI:

- Новый модуль `memora-api/src/llm/` c единственной точкой входа
  (`chat(request) -> stream | text`), внутри — OpenAI chat completions формат.
- Конфигурация через env (совместимость со старыми переменными сохранить):
  - `LLM_BASE_URL` (дефолт — Ollama Cloud `/v1`), `LLM_API_KEY`, `LLM_MODEL`;
  - опциональные переопределения по задачам: `LLM_MODEL_GENERATION` (тяжёлая генерация юнитов/вариантов),
    `LLM_MODEL_GRADING` (оценка ответов), `LLM_MODEL_CHAT` (тьютор/диалоги) — лёгкое на дешёвой
    модели, тяжёлое на сильной;
  - `LLM_FALLBACK_BASE_URL/KEY/MODEL` — резервный провайдер при 5xx/таймауте (устойчивость коуча).
- **Structured outputs**: везде, где ждём JSON (генерация юнитов, вариантов, оценка), передавать
  `response_format: json_schema` — убирает «вырезание JSON из markdown» (`extract_json`) и битые ответы.
- Переключить все 12+ вызовов в `ai.rs` на новый модуль; поведение по умолчанию (Ollama Cloud,
  `gpt-oss:120b`) не меняется.

### 0.2 Довести Фазу 1 Subject Packs (по спеке, слайсы 3–8)
- DTO: типизированный `answer` (`answer.kind`) + `rule.level` с фолбэком на `rule.cefr`.
- `courses.rs`: принимать/возвращать `subject`; валидация типов упражнений из пака.
- `generate_course_unit`: персона и `allowed_types` из пака.
- `audio.rs`: голос из пака; ключ `tts_cache` включает голос (существующий FR-кэш не инвалидировать).
- Пилот `language-en` — проверка обобщённости до STEM.

### 0.3 Гигиена репозитория (быстро, важно)
- Убрать из репо `cookies.txt`, `raw_token.txt`, `new_session.json` (+ в `.gitignore`),
  проверить историю git на секреты (ключ Inworld уже засветился ранее — отозвать, если не сделано).
- Учебные материалы (`Учебники/`, `Édito A2…`, `Les verbes/`, mp4) — в `.gitignore` или отдельное хранилище
  (они же — будущий корпус для ингеста, см. 2.4).

## Фаза 1 — коуч: полноценный тренер (главный приоритет)

Цель: замкнуть цикл «диагностика → тренировка → выявление слабого места → прицельная
проработка → полное усвоение», где материал **не заканчивается и не повторяется дословно**.

### 1.1 Mastery по навыкам (ядро адаптивности)
Сейчас FSRS живёт на уровне упражнения. Вводим агрегат по `rule.skill`:

- Представление `skill_mastery` (view или материализация): по (`user`, `course`, `skill`) считаем
  из `course_exercise_reviews` + `course_review_logs`: долю усвоенных (state=2), частоту «Again/Hard»
  за окно 30 дней, среднюю stability. Итог — оценка 0–100 и статус: `new / learning / weak / mastered`.
- `GET /api/courses/{id}/coach/skills` — карта навыков для UI и для планировщика сессии.
- Слабое место = навык со статусом `weak` (высокая доля Again/Hard при достаточном числе попыток).

### 1.2 Планировщик сессии на сервере
Сейчас очередь строит фронтенд («due → новые»). Переносим на сервер и делаем умнее:

- `GET /api/courses/{id}/coach/session-plan` возвращает готовую очередь:
  1) просроченные повторения (FSRS due),
  2) **прицельная практика по 1–2 самым слабым навыкам** (см. 1.4),
  3) новый материал в пределах дневной цели,
  4) микс карточек лексики (уже миксуется — сохранить).
- Interleaving: упражнения одного навыка не идут подряд; чередование форматов.
- План на день учитывает цели пользователя (минуты/новые упражнения — уже есть в стартовом экране).

### 1.3 Генерация свежих вариантов при каждом повторе (обобщение Voltaire-слоя)
`course_exercise_variants` + `regenerate_variant` уже работают для `error-hunt`.
Обобщаем на все типы упражнений пака:

- При показе повторения (state=learning/review) сервер выдаёт **новый вариант того же правила**:
  LLM-генерация по `rule.skill`/`rule.point`/`rule.trap` эталонного упражнения, формат — из
  `variantPolicy.format` или тип эталона (`grammar-quiz`, `fill-blank`, `sentence-builder`…).
- Анти-повтор: `avoidLastN` по таблице вариантов (уже заложено), фолбэк на эталон при недоступности LLM.
- **Фоновая прегенерация**: ночной/фоновый воркер (tokio task) смотрит, какие правила у пользователя
  due завтра, и заранее кладёт 1–2 варианта в таблицу. Латентность LLM исчезает из сессии,
  квота Ollama Cloud расходуется в тихие часы. Это и есть «максимум пользы от облачного Ollama».
- Structured outputs (0.1) здесь критичны — вариант обязан пройти детерминированную валидацию
  (у `grammar-quiz` есть правильный индекс, у `fill-blank` — ответ и т.д.) перед сохранением.

### 1.4 Прицельная проработка слабых мест
- Обобщить `generate_practice` (сейчас «по ошибочным упражнениям») до «по слабому навыку»:
  вход — `skill` + последние ошибки пользователя из логов, выход — 4–8 новых упражнений
  с нарастающей сложностью.
- Режим «Проработка»: отдельная кнопка у слабого навыка на карте навыков и автоматическая
  вставка в сессию (1.2). Навык выходит из статуса `weak` только по результатам FSRS —
  то есть после успешных повторений во времени, а не после одной удачной серии.
- Умные дистракторы: в генерируемых MCQ варианты строить из типичных ошибок пользователя
  (`course_review_logs` + сохранённые неверные ответы — добавить колонку `answer_given` в лог).

### 1.5 Сократический тьютор (лестница подсказок)
После ошибки — не сразу правильный ответ, а эскалация:
1) короткая подсказка (без ответа) → 2) наводящий вопрос (LLM, контекст упражнения и ответа
ученика — инфраструктура `explain_exercise` уже есть) → 3) полное объяснение →
4) сразу новый вариант того же правила для закрепления (из 1.3).
Каждая ступень понижает авто-рейтинг FSRS (без подсказки = Good/Easy, с подсказкой = Hard, не справился = Again).

### 1.6 UI коуча
- **Карта навыков**: сетка навыков курса с цветом статуса и кнопкой «проработать».
- Экран итогов сессии: что усвоено, что в слабых, прогноз «курс будет усвоен к …».
- Push-напоминания через PWA (перенос из прошлого плана; для семьи это главный retention-механизм).

## Фаза 2 — иностранные языки: новые форматы

### 2.1 Диктант (dictée) — метод Projet Voltaire
TTS (Inworld, уже есть) читает фразу → ученик печатает → **детерминированная** проверка с
diff-подсветкой по словам; ошибки мапятся на навыки (орфография/гомофоны — база `voltair_fr` уже наработана).
Новый тип упражнения `dictation` (answer.kind = cloze-подобный, проверка на сервере без LLM).

### 2.2 Голосовой коуч (замкнуть уже готовые части)
`converse` (LLM-диалог) + Inworld TTS + `/api/audio/transcribe` уже существуют по отдельности —
собрать в непрерывный голосовой режим: ИИ говорит → ученик отвечает голосом → транскрипция →
оценка уместности и разбор ошибок → следующая реплика. Плюс shadowing-режим на базе
`pronunciation.rs`: повтори фразу, сравнение транскрипции с эталоном.

### 2.3 Истории v2
К существующей генерации историй добавить: пропуски в тексте (история = упражнение),
клик по слову → перевод + озвучка + «в словарь» (карточка с FSRS), уровни сложности истории
по прогрессу ученика.

### 2.4 Ингест учебников («курс из PDF»)
Папка `Учебники/` — готовый корпус. Конвейер: PDF/EPUB → извлечение текста по главам →
pgvector (расширение на Railway Postgres) → грунтованная генерация юнитов
(`generate_course_unit` уже умеет «по вставленному тексту» — добавить выбор источника и глав).
Аудио-учебники → Whisper-транскрипция → упражнения на аудирование из реальных диалогов.

### 2.5 Новые языки
`language-en` (пилот Фазы 0) → `language-de`, `language-es`: только контент, голос Inworld
и персона промпта — архитектура уже готова.

## Фаза 3 — математика, физика, история (французская школьная программа)

### 3.1 Уровни: французская школа
`LevelScheme::Grade` со шкалой **6e, 5e, 4e, 3e (collège), 2nde, 1re, Terminale (lycée)**.
Контент и формулировки — на французском (двойная польза: предмет + язык); объяснения
ошибок — на русском или французском по настройке пользователя (у `explain_exercise` уже
русскоязычные объяснения — сделать язык параметром).

### 3.2 Паки
- `math-fr`: персона «professeur de mathématiques, programme français, classe de {level}»;
  типы: `mcq`, `numeric`, `symbolic` (позже), `short-text`.
- `physique-chimie-fr`: `mcq`, `numeric` (с единицами измерения), `short-text`.
- `histoire-fr`: `mcq`, `ordering` (хронология), `short-text`/`open-rubric`, `cloze` (даты/термины).

### 3.3 Валидаторы (главный риск — снимаем детерминированностью)
LLM **не проверяет** математику. По `answer.kind`:
- `numeric` (Rust, сразу): парсинг числа с запятой/точкой, допуск (`tolerance`), приведение
  единиц (см/м, г/кг) по таблице; для физики обязательна проверка единицы в ответе.
- `ordering` (Rust, сразу): сравнение последовательности — хронология, этапы решения.
- `symbolic` (позже, отдельный слайс): микросервис SymPy (Python/FastAPI) вторым сервисом
  на Railway — эквивалентность выражений (`2(x+1)` == `2x+2`). До него — обходиться
  `numeric` + MCQ, этого хватает на большую часть collège.
- `open-rubric` (история): LLM-оценка по рубрике из 2–4 критериев с обязательной цитатой-обоснованием.

### 3.4 Слабые места в STEM = misconceptions
`rule.trap` («ловушка») переносится напрямую: «знак при переносе через равно»,
«путает vitesse и accélération», «смешивает причину и повод». Вся машинерия Фазы 1
(mastery по `rule.skill`, прицельная генерация, сократическая лестница) работает без изменений —
это и была цель порядка фаз.

### 3.5 Контент
Стартовые курсы генерировать по официальным программам Éducation nationale (темы по классам),
juntить с ингестом (2.4) французских школьных учебников, если появятся PDF.

## Максимум пользы от Ollama Cloud (сквозная тема)

1. **Фоновая прегенерация вариантов** (1.3) — тяжёлая генерация уходит из интерактивного пути.
2. **Structured outputs** (0.1) — ноль ретраев на битом JSON, экономия квоты.
3. **Модель по задаче**: подсказки/оценка на лёгкой модели, генерация юнитов/вариантов — на
   сильной (`LLM_MODEL_*`), тяжёлые DeepSeek/Qwen из каталога Ollama Cloud — только там, где надо.
4. **Кэш навсегда**: каждый сгенерированный вариант сохраняется в `course_exercise_variants` —
   при исчерпании квоты коуч работает на накопленном пуле (фолбэк уже спроектирован).
5. **Резервный провайдер** (0.1): при недоступности Ollama Cloud — автоматический переход на
   запасной OpenAI-совместимый endpoint без деградации сессии.
