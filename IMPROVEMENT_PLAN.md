# Memora — план развития платформы

> **Обновление (вечер 10 июня 2026):** приоритеты 1–3 реализованы. Коуч получил стартовый экран с планом на день, целями и серией дней (streak); оценки ставятся автоматически по результату упражнения; в сессию миксуется лексика юнитов; появилась кнопка «Я уже это знаю» (быстрая диагностика). Добавлены ИИ-тьютор «Не понимаю — объясни», доп. практика по слабым местам, разговорная практика с голосовым вводом и озвучкой, чтение ИИ-историй из лексики курса, экзамены юнитов с таймером и проходным баллом 80%, страница «Мой прогресс» (усвоение по юнитам, прогноз повторений на неделю, слабые места). Также исправлена сборка на Railway (cp в кэш-маунте nixpacks). Ниже — исходный план; нереализованным остаётся пункт push-напоминаний и часть «Приоритета 4».

Дата: 10 июня 2026. Документ описывает, что уже сделано в этой итерации и что предлагается дальше, чтобы превратить Memora из набора тренажёров в полноценного персонального коуча.

## Что сделано в этой итерации

Исправлены ошибки и уязвимости: убран захардкоженный ключ Inworld из кода (ключ нужно отозвать и перевыпустить — он остался в истории git), эндпоинты TTS и диагностики закрыты авторизацией, добавлены rate-limit и проверки доступа на всех AI-эндпоинтах, устранена возможность перезаписи чужих карточек, починен сломанный компонент генерации озвучки, исправлена потеря данных в SSE-стриминге LLM и нарушение правил React hooks.

Добавлен конструктор курсов: любой пользователь создаёт курс (раздел «Курсы» → «Создать курс»), наполняет юниты теорией, тестами, диалогами, упражнениями на пропуски, сборку предложений, род, аудирование и видео — тот же формат, что у Édito A1, поэтому всё рендерится существующими компонентами и озвучивается через Inworld. Контент юнита можно сгенерировать ИИ по теме или по вставленному тексту учебника. Курс публикуется для всех пользователей одной кнопкой.

Добавлен коуч-режим (для Édito A1 и любых новых курсов): платформа сама решает, что тренировать — сначала то, чему подошёл срок повторения, затем новый материал. После каждого упражнения учащийся оценивает сложность («Снова / Трудно / Хорошо / Легко»), и алгоритм FSRS планирует следующее повторение. Материал считается усвоенным, когда переходит в долговременное повторение; «Снова» возвращает упражнение в ту же сессию. Это и есть цикл «обучение → проверка → повтор невыученного → полное усвоение».

## Приоритет 1 — довести коуча до полноценного тренера

**Ежедневный план и цели.** Стартовый экран коуча: «Сегодня: 4 повторения, 6 новых упражнений, ~15 минут». Настройка целей (минут в день, новых упражнений в день), серия дней (streak) и напоминания (push через существующую PWA-инфраструктуру). Это главный механизм удержания и регулярности — без регулярности интервальное повторение не работает.

**Автоматическая оценка вместо самооценки.** Сейчас учащийся сам оценивает сложность. Компоненты упражнений уже знают количество ошибок — стоит прокинуть из них результат (ошибки, время) и вычислять рейтинг FSRS автоматически: без ошибок и быстро = «Легко», с 1–2 ошибками = «Трудно», не справился = «Снова». Самооценку оставить как уточнение.

**Диагностика при входе в курс.** Короткий адаптивный тест перед началом (как уже сделано в A2): коуч помечает уже известные темы как усвоенные и не тратит время учащегося. 

**Интеграция словаря в коуча.** Лексика юнитов уже синхронизируется в наборы карточек с FSRS. Коуч должен миксовать в сессию и карточки слов: «3 слова на повторение + 2 упражнения». Одна сессия — один вход, всё в одном потоке.

## Приоритет 2 — более интересная подача материала

**ИИ-тьютор в контексте упражнения.** Кнопка «Не понимаю» у любого упражнения: LLM объясняет конкретную ошибку учащегося с учётом его уровня, на русском, с примерами (инфраструктура Q-Chat уже есть — нужно дать ей контекст упражнения и ошибки). Это превращает проверку в обучение.

**Бесконечная практика по слабым темам.** Эндпоинт генерации A2-заданий уже умеет создавать новые задания по слабым темам. Распространить на все курсы: коуч смотрит статистику ошибок (`error-stat` уже собирается) и догенерирует упражнения именно там, где учащийся ошибается, — материал не заканчивается, пока тема не усвоена.

**Геймификация.** XP и лидерборды уже есть в A2 — обобщить на все курсы: XP за сессии коуча, уровни, достижения («7 дней подряд», «100 упражнений», «юнит без ошибок»), еженедельные лиги. Дёшево в реализации, сильно влияет на мотивацию.

**Разговорная практика.** Связка уже имеющихся возможностей: Inworld TTS (озвучка реплик) + транскрипция (`/api/audio/transcribe`) + LLM-оценка ответа = диалоговый тренажёр, где учащийся отвечает голосом, а ИИ оценивает произношение и уместность ответа. Это самый востребованный формат для языковых курсов.

**Истории и контекстное чтение.** Генерация коротких текстов уровня учащегося из его словаря (LLM), с кликабельными словами (перевод + озвучка + добавить в словарь). Чтение — лучший способ закрепления лексики в контексте.

## Приоритет 3 — проверка знаний

**Экзамен юнита и курса.** Сводный тест по юниту (микс типов упражнений, без подсказок, с таймером) как условие «прохождения» юнита; финальный экзамен курса с сертификатом. Оценка письменных ответов через уже существующий AI-grade эндпоинт.

**Умные дистракторы.** В тестах генерировать варианты ответов из типичных ошибок учащегося (статистика ошибок уже собирается) — проверка становится прицельной.

**Отчёт о прогрессе.** Страница аналитики для учащегося: кривая усвоения, прогноз («при текущем темпе курс будет усвоен к …»), слабые темы. Для преподавателя в группах — то же по каждому ученику (teacher overview уже частично есть в A2).

## Приоритет 4 — платформа и качество

Технический долг, обнаруженный при аудите, который стоит закрыть:

- CORS на бэкенде разрешает любые origin — сузить до доменов фронтенда.
- `get_public_set` намеренно отдаёт приватные наборы по прямой ссылке (UUID как «капабилити»). Если это не осознанное решение — добавить проверку `is_public || owner`.
- В `update_set` карточки перезаписываются всем списком на каждое сохранение — при больших наборах стоит перейти на дифф.
- Тестов почти нет: добавить интеграционные тесты хотя бы на auth, sets CRUD, courses CRUD и coach review (sqlx + testcontainers), e2e smoke на Playwright.
- `generate_exercises`/`analyze_content` парсят SSE-чанки без буферизации строк (исправлено только в основных стримах) — привести к общему хелперу.
- Маршрут `/api/diag/db` со временем удалить совсем.
- В CI добавить `cargo clippy` и `npm run lint` (сейчас только check/build).

## Архитектурная заметка о курсах

Пользовательские курсы хранятся в Postgres (`custom_courses` / `custom_course_units`, контент юнита — JSONB в формате Édito). Встроенные курсы остаются в бандле фронтенда. Когда конструктор обкатается, имеет смысл мигрировать Édito A1 в БД тем же форматом (скрипт сидирования из JSON уже тривиален) — тогда и его можно будет править через редактор, а специальные страницы останутся только у A1/A2-тренажёров.
