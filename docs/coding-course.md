# Раздел «Программирование»: Python + SQL с песочницами в браузере

Учебные курсы для тех, кто **никогда не программировал** — включая детей 14 лет и
младше — и для тех, кто уже знает основы и хочет прикладных навыков (аналитика данных,
ООП, статистика). Пять треков, игровая подача, задачи решаются в песочнице прямо на
странице урока. Аналог pythontutor.com/python-compiler, но свой, встроенный в Memora и
с автопроверкой решений.

## Что это даёт

| | 🐍 Python | 🐘 SQL | 📊 Аналитика данных | ⚔️ ООП | 🎲 Статистика |
|---|---|---|---|---|---|
| Название | Академия юных кодеров | Детектив данных | Python и SQL для аналитика данных | ООП на Python | Статистика и вероятность для аналитика |
| Для кого | с нуля, дети и взрослые | с нуля, дети и взрослые | прошёл базовые Python и SQL | прошёл базовый Python | прошёл базовый Python |
| Уроков | 14 | 11 | 11 | 11 | 12 |
| Задач с автопроверкой | 44 | 30 | 21 (9 Python + 12 SQL) | 22 | 19 |
| Викторин / вопросов | 14 / 38 | 11 / 28 | 11 / 23 | 11 / 23 | 12 / 26 |
| Движок песочницы | Pyodide | PGlite (**PostgreSQL**) | Pyodide **и** PGlite вместе | Pyodide | Pyodide |

Итого по всем 5 трекам: 59 уроков, 136 задач, 59 викторин (138 вопросов), 110 блоков теории,
≈3950 XP при полном прохождении.

Программа Python (с нуля): `print` → переменные → арифметика (порядок операций) → f-строки
и методы строк (`len`, `.upper()`, `.lower()`) → `if/elif/else` и логика `and`/`or` →
списки, индексация с нуля и `in` → `for`/`range` (в том числе узоры звёздочками через
повторение строк) → `while` → функции и `return` (включая несколько параметров) →
**простые типы данных** (`int`/`float`/`str`/`bool`/`None`, `type()`, конвертация
`int()`/`str()`) → **словари и множества** (пары «ключ→значение», уникальные значения,
перечисления через словарь-подстановку) → **кортежи, координаты и векторы** (неизменяемые
`tuple`, распаковка, 2D/3D-координаты, сложение векторов, длина вектора через
`math.sqrt`) → **работа с файлами** (`open`/`with`, режимы `"w"`/`"r"`/`"a"`, чтение по
строкам и `.strip()`) → финальный проект. Каждый урок — минимум 3 практических задачи вместо
прежних двух, для детей это больше повторений на одну и ту же идею с новыми игровыми
сценариями.

Программа SQL (с нуля): таблицы и `SELECT *` (включая `LIMIT`-подсказку) → выбор столбцов
и `DISTINCT` → `WHERE`/`AND`/`OR` → поиск по маске `LIKE` и `%` (детективная тема: «имя
начинается на...», «где-то есть буквы...») → `ORDER BY`/`LIMIT`, включая сортировку по
тексту → `COUNT`/`SUM`/`AVG`/`MIN`/`MAX` → `GROUP BY` → `INSERT`/`UPDATE`/`DELETE` (с
акцентом «не забудь `WHERE`», и впервые — практика самого `DELETE`, не только показ в
теории) → `JOIN` (с промежуточным шагом `JOIN` + `WHERE`) → **представления** (`CREATE VIEW`,
запрос как виртуальная таблица, `WHERE`/`COUNT(DISTINCT ...)` поверх VIEW) → **оконные
функции для новичков** (`ROW_NUMBER() OVER (ORDER BY ...)` и `RANK()`, разница в обработке
повторов) и финальное расследование.

Программа «Аналитика данных» (продвинутый, продолжение основ): `csv.DictReader` и парсинг
текстовых данных → `statistics` (среднее, медиана, стандартное отклонение) → `Counter`/
`defaultdict` для группировки без SQL → оконные функции (`ROW_NUMBER`, `SUM() OVER`) →
`WITH`-CTE и подзапросы → `DATE_TRUNC`/`EXTRACT` → сводные таблицы (`CASE WHEN` + `GROUP BY`)
→ `JOIN`/`LEFT JOIN` двух таблиц → `LAG`/`LEAD` для сравнения периодов (рост месяц-к-месяцу)
→ `HAVING` и очистка текста (`TRIM`, `LOWER`, `COALESCE`) → финальный кейс, объединяющий
Python и SQL в одном уроке. Сквозные наборы данных — витрина продаж интернет-магазина за
квартал (`sales`), менеджеры по регионам (`managers`, для урока про JOIN) и «грязные»
отзывы покупателей (`feedback`, для урока про HAVING/очистку).

Программа «ООП на Python» (продвинутый, продолжение основ Python): от словаря к классу →
методы и `self` → изменение состояния объекта → инкапсуляция (`@property`, `_атрибут`) →
наследование (`super().__init__()`) → полиморфизм и `isinstance` → магические методы
(`__str__`, `__eq__`, `__len__`) → атрибуты класса и `classmethod`/`staticmethod` →
собственные исключения (`raise`, `class MyError(Exception)`) → абстрактные классы
(`abc.ABC`, `@abstractmethod`) → финальный проект (композиция классов `Item` + `Inventory`).
Сквозной сюжет — отряд героев готовится к походу (Hero, Mage, Healer, Inventory, Enemy).

Программа «Статистика и вероятность для аналитика» (продвинутый, продолжение основ
Python, чистый `statistics`/`math`/`random` из стандартной библиотеки — без numpy/pandas):
числовые vs категориальные данные, `len`/`sum`/`min`/`max` → `statistics.mean()` и
`round()` → медиана и мода против выбросов (`statistics.median`/`mode`) → размах и
межквартильный разброс (`statistics.quantiles`, IQR) → дисперсия и стандартное отклонение
(`pvariance`/`pstdev`, population vs выборка) → основы вероятности и закон больших чисел
(`random.seed`, симуляция бросков кубика) → нормальное распределение и правило 68-95-99.7 →
корреляция и ловушка «корреляция ≠ причинность» (`statistics.correlation`) → выборка и
генеральная совокупность (`random.sample`) → доверительные интервалы (`math.sqrt`,
стандартная ошибка) → основы A/B-тестирования (конверсия, z-оценка значимости) →
финальный кейс аналитика, сравнивающий стабильность двух команд поддержки. Каждый числовой
результат в каждой задаче проверен реальным запуском в Pyodide перед тем, как попасть в
эталон `expectedOutput` — в том числе банковское округление на границах `.5` и
детерминированность `random.seed()`.

## Маршруты

```
/coding                        хаб: треки, уровень, XP, награды
/coding/[trackId]              карта уроков трека (python | sql | data-analyst | oop | statistics)
/coding/[trackId]/[lessonId]   урок: теория → задачи → викторина
/coding/playground             свободная песочница без заданий (Python и SQL)
```

Раздел **не требует авторизации** (его нет в matcher'е `src/middleware.ts`) — ребёнок может
начать учиться сразу, что снижает порог входа. Прогресс хранится локально, поэтому
приватность не страдает.

## Архитектура

```
src/data/coding/

  python-course.ts          трек «Академия юных кодеров» (с нуля)
  sql-course.ts              трек «Детектив данных» (с нуля, + seed-SQL)
  data-analyst-course.ts     трек «Аналитика данных» (продвинутый, Python + SQL вместе)
  oop-course.ts              трек «ООП на Python» (продвинутый)
  statistics-course.ts       трек «Статистика и вероятность для аналитика» (продвинутый)
  index.ts                   реестр треков, getTrack / getLesson
src/lib/coding/
  pyRunner.ts         запуск Python в Web Worker (Pyodide)
  sqlRunner.ts        запуск SQL в PGlite + сравнение результатов
  progress.ts         XP / уровни / награды в localStorage (useSyncExternalStore)
src/components/coding/
  LessonPlayer.tsx    плеер урока, начисление XP и выдача наград
  PyTask.tsx          Python-задача: редактор + запуск + проверка
  SqlTask.tsx         SQL-задача: редактор + запуск + таблица результата
  Quiz.tsx            мини-викторина
  CodeEditor.tsx      редактор с номерами строк, Tab = 4 пробела
  TaskShell.tsx       условие, подсказки, решение после 3 неудач, баннер успеха
  XpBadge.tsx         виджет уровня и XP

  copy-sandbox-assets.mjs   копирует Pyodide и PGlite из node_modules в public/sandbox
```

Контент — **в коде фронтенда**, как и предусмотрено для Фазы 1 в `subject-packs-spec.md`:
Rust-бэкенд, БД и FSRS-повторения не затронуты, французский курс не может сломаться.

Один урок может свободно смешивать `py-task` и `sql-task` в одном списке `blocks` —
именно так сделан финальный урок трека «Аналитика данных» (`final-keys-analitika`):
Python-задача на расчёт роста выручки, затем SQL-задача с CTE и `RANK()`. Компонент
`LessonPlayer` рендерит блоки по `kind` независимо от трека, поэтому новых компонентов
для такого смешения не потребовалось.

### Почему ассеты свои, а не с CDN

Pyodide (~13 МБ) и PGlite (~13 МБ) копируются из `node_modules` в `public/sandbox/`
скриптом `scripts/copy-sandbox-assets.mjs`. Он запускается автоматически через хуки
`predev` и `prebuild`, а сами файлы в git **не коммитятся** (`.gitignore`).

Причины раздавать со своего домена:

- Memora — PWA: песочницы должны работать в офлайне и за школьными фаерволами;
- нет зависимости от доступности сторонних CDN и утечки трафика учеников на них;
- версия зафиксирована в `package.json`, а не в строке URL внутри кода.

Ассеты грузятся лениво — только когда ученик открывает урок или песочницу,
поэтому на остальные страницы Memora это не влияет.

### Безопасность и защита от «повесить браузер»

- **Python исполняется в Web Worker.** Бесконечный цикл (`while True:`) не блокирует
  страницу: через 15 секунд воркер убивается, ученик видит понятное сообщение
  «Программа выполнялась слишком долго», и песочница сразу готова к следующему запуску.
- **Каждый запуск Python — в чистом пространстве имён** (`pyodide.globals.get("dict")()`),
  задачи не влияют друг на друга.
- **SQL: перед каждым запуском схема `public` пересоздаётся** и наполняется seed-скриптом
  урока. Ученик может смело выполнить `DROP TABLE` — следующий запуск снова получит
  корректные данные, а результат задачи всегда воспроизводим. Запуски сериализуются
  через очередь, потому что инстанс PGlite один.
- Код никуда не отправляется: всё исполняется в браузере ученика, сервер не участвует.

### Проверка решений

Python (`PyCheck`): точный ожидаемый вывод, либо обязательные подстроки в выводе,
либо обязательные конструкции в коде (`codeContains: ["for", "range"]` — чтобы задачу
на цикл нельзя было решить копипастой четырёх `print`).

SQL (`SqlCheck`): сравнение строк результата (с опцией `orderMatters` для `ORDER BY`),
либо контрольный запрос после `INSERT`/`UPDATE`/`DELETE` (`checkQuery` + `checkRows`),
либо обязательные ключевые слова (`codeContains: ["update", "set", "where"]`).

### Геймификация

XP за каждую задачу и викторину (10–35), 17 уровней (🥚 Новичок → 👑 Легенда курса Memora на
3850 XP — пороги растянуты на суммарные ~3950 XP всех 5 треков, чтобы верхний уровень не
открывался на середине первого трека), награда за каждый пройденный урок и за весь трек. XP за одно
задание начисляется **один раз** — повторное решение не накручивает опыт. Подсказки
открываются по одной, эталонное решение — только после 3 неудачных попыток.

Прогресс лежит в `localStorage` под ключом `memora-coding-progress-v1` и читается через
`useSyncExternalStore`, поэтому счётчик XP в шапке и прогресс-бары обновляются
одновременно во всех виджетах страницы.

### Цвет трека и Tailwind

`Track.color` — один из `"green" | "blue" | "purple" | "orange" | "teal" | "pink" | "cyan" | "amber"`.
На хабе (`coding/page.tsx`)
цвет резолвится через статическую таблицу `TRACK_STYLE`, а не сборкой строки класса на
лету (`` `border-${accent}-500` ``) — динамические имена классов Tailwind v4 не всегда
подхватывает при сканировании исходников, поэтому все варианты выписаны явно как
литералы. При добавлении нового цвета трека обязательно добавь его в `TRACK_STYLE`.

## Как добавить урок или задачу

Урок — это объект в массиве `lessons` соответствующего трека. Минимальный пример задачи:

```ts
{
  kind: "py-task",
  id: "z1",
  title: "Название задачи",
  story: ["Игровое условие. Можно `код в бэктиках`."],
  starterCode: "# подсказка-заготовка\n",
  check: { expectedOutput: "42", codeContains: ["*"] },
  hints: ["Первая подсказка", "Вторая — конкретнее"],
  solution: "print(6 * 7)",
  xp: 20,
}
```

Для SQL-урока таблицы задаются один раз в `lesson.seedSql` и доступны всем задачам урока.
Блоки `py-task` и `sql-task` можно свободно чередовать в одном уроке (см. выше).

**После добавления обязательно проверьте, что эталонное решение проходит собственный
чекер** — иначе задача окажется нерешаемой. Тест из раздела ниже делает это автоматически.

Для новых SQL-задач удобно проверить точный результат запроса ещё до написания теста:
`@electric-sql/pglite` работает не только в браузере, но и напрямую под Node.js —
`new (require("@electric-sql/pglite").PGlite)()` — поэтому можно прогнать seed + запрос
локально и скопировать реальный результат в `expected.rows`, не считая вручную. Так же
можно проверить Python-вывод: пакет `pyodide` (не только `pyodide.js` в браузере) грузится
и в Node через `loadPyodide()` из npm-пакета `pyodide`.

## Тестирование

Раздел проверялся в реальном Chromium (Playwright) на собранной production-сборке,
семь раз — при первом запуске (Python + SQL), при добавлении «Аналитики данных» и «ООП»,
при расширении обоих продвинутых треков темами JOIN/LAG-LEAD/HAVING и
classmethod/исключения/ABC, при добавлении практики и новых тем (LIKE, DISTINCT,
and/or, узоры звёздочками и т.д.) в базовые треки Python и SQL, при добавлении в Python
четырёх новых уроков (типы данных, словари/множества, координаты/векторы, файлы), при
добавлении в SQL представлений (VIEW) и оконных функций для новичков (ROW_NUMBER, RANK),
и при добавлении нового трека «Статистика и вероятность для аналитика» (12 уроков):

- сценарии UI: навигация, начисление и неповторное начисление XP, награды,
  разблокировка уроков, подсказки, решение после 3 неудач, 404 на несуществующий урок,
  прерывание бесконечного цикла и восстановление песочницы после него,
  пересоздание базы после `DROP TABLE`, отклонение `UPDATE` без `WHERE`,
  корректный рендер урока со смешанными Python+SQL блоками;
- **136/136 эталонных решений** (все 5 треков) проходят свой чекер — каждая задача решаема;
- **59/59 викторин** (138 вопросов) засчитывается при выборе правильных вариантов.

Идея прогона всех решений: собрать данные курса в CJS (`npx esbuild src/data/coding/index.ts
--bundle --format=cjs --platform=node`), затем для каждой задачи подставить `solution`
в редактор и убедиться, что появился баннер «Задача решена!». При смешанных py+sql уроках
индекс кнопки нужно считать раздельно по типу задачи (`pyIdx`/`sqlIdx`), а не по общей
позиции блока — иначе `locator("button", {hasText}).nth(i)` уйдёт в таймаут на уроке,
где кнопок каждого вида меньше, чем общее число задач.

## Что дальше (Фаза 2, необязательно)

Спецификация `subject-packs-spec.md` позволяет подключить курсы к ядру повторений:
добавить subject-pack `code` в Rust-бэкенде, сохранять решённые задачи как
`course_exercise_reviews` (FSRS) и показывать прогресс в семейном табло.
Формат задач уже совместим по смыслу: `rule.skill` ↔ навык, `rule.trap` ↔ типичная ошибка
(например, «счёт списков с нуля», «`=` вместо `==`» или «UPDATE без WHERE»).

Возможные следующие треки по той же схеме: JavaScript/веб-основы, регулярные выражения,
git, тестирование (pytest). Технической подготовки для этого не требуется — Pyodide и
PGlite уже развёрнуты, добавление трека — это только новый файл в `src/data/coding/`.
