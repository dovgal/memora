# Раздел «Программирование»: Python + SQL с песочницами в браузере

Учебный курс для тех, кто **никогда не программировал** — включая детей 14 лет и младше.
Два трека, игровая подача, задачи решаются в песочнице прямо на странице урока.
Аналог pythontutor.com/python-compiler, но свой, встроенный в Memora и с автопроверкой решений.

## Что это даёт

| | Python-трек | SQL-трек |
|---|---|---|
| Название | 🐍 Академия юных кодеров | 🐘 Детектив данных |
| Уроков | 10 | 8 |
| Задач с автопроверкой | 21 | 15 |
| Викторин / вопросов | 10 / 21 | 8 / 17 |
| Движок песочницы | Pyodide (CPython → WASM) | PGlite (**настоящий PostgreSQL** → WASM) |

Итого: 18 уроков, 36 задач, 18 викторин (38 вопросов), 26 блоков теории.

Программа Python: `print` → переменные → арифметика → f-строки → `if/elif/else` →
списки и индексация с нуля → `for`/`range` → `while` → функции и `return` → финальный проект.

Программа SQL: таблицы и `SELECT *` → выбор столбцов → `WHERE`/`AND`/`OR` →
`ORDER BY`/`LIMIT` → `COUNT`/`SUM`/`AVG`/`MAX` → `GROUP BY` →
`INSERT`/`UPDATE`/`DELETE` (с акцентом «не забудь `WHERE`») → `JOIN` и финальное расследование.

## Маршруты

```
/coding                        хаб: треки, уровень, XP, награды
/coding/[trackId]              карта уроков трека (python | sql)
/coding/[trackId]/[lessonId]   урок: теория → задачи → викторина
/coding/playground             свободная песочница без заданий (Python и SQL)
```

Раздел **не требует авторизации** (его нет в matcher'е `src/middleware.ts`) — ребёнок может
начать учиться сразу, что снижает порог входа. Прогресс хранится локально, поэтому
приватность не страдает.

## Архитектура

```
src/data/coding/
  types.ts            типы контента (блоки урока, форматы проверки)
  python-course.ts    весь Python-трек как данные
  sql-course.ts       весь SQL-трек как данные (+ seed-SQL для таблиц)
  index.ts            реестр треков, getTrack / getLesson
src/lib/coding/
  pyRunner.ts         запуск Python в Web Worker (Pyodide)
  sqlRunner.ts        запуск SQL в PGlite + сравнение результатов
  progress.ts         XP / уровни / награды в localStorage (useSyncExternalStore)
src/components/coding/
  LessonPlayer.tsx    плеер урока, начисление XP и выдача наград
  PyTask.tsx          Python-задача: редактор + запуск + проверка
  SqlTask.tsx         SQL-задача: редактор + запуск + таблица результата
  Quiz.tsx            мини-викторина
  CodeEditor.tsx      редактор с номерами строк, Tab = 4 пробела
  TaskShell.tsx       условие, подсказки, решение после 3 неудач, баннер успеха
  XpBadge.tsx         виджет уровня и XP
scripts/
  copy-sandbox-assets.mjs   копирует Pyodide и PGlite из node_modules в public/sandbox
```

Контент — **в коде фронтенда**, как и предусмотрено для Фазы 1 в `subject-packs-spec.md`:
Rust-бэкенд, БД и FSRS-повторения не затронуты, французский курс не может сломаться.

### Почему ассеты свои, а не с CDN

Pyodide (~13 МБ) и PGlite (~13 МБ) копируются из `node_modules` в `public/sandbox/`
скриптом `scripts/copy-sandbox-assets.mjs`. Он запускается автоматически через хуки
`predev` и `prebuild`, а сами файлы в git **не коммитятся** (`.gitignore`).

Причины раздавать со своего домена:

- Memora — PWA: песочницы должны работать в офлайне и за школьными фаерволами;
- нет зависимости от доступности сторонних CDN и утечки трафика учеников на них;
- версия зафиксирована в `package.json`, а не в строке URL внутри кода.

Ассеты грузятся лениво — только когда ученик открывает урок или песочницу,
поэтому на остальные страницы Memora это не влияет.

### Безопасность и защита от «повесить браузер»

- **Python исполняется в Web Worker.** Бесконечный цикл (`while True:`) не блокирует
  страницу: через 15 секунд воркер убивается, ученик видит понятное сообщение
  «Программа выполнялась слишком долго», и песочница сразу готова к следующему запуску.
- **Каждый запуск Python — в чистом пространстве имён** (`pyodide.globals.get("dict")()`),
  задачи не влияют друг на друга.
- **SQL: перед каждым запуском схема `public` пересоздаётся** и наполняется seed-скриптом
  урока. Ученик может смело выполнить `DROP TABLE` — следующий запуск снова получит
  корректные данные, а результат задачи всегда воспроизводим. Запуски сериализуются
  через очередь, потому что инстанс PGlite один.
- Код никуда не отправляется: всё исполняется в браузере ученика, сервер не участвует.

### Проверка решений

Python (`PyCheck`): точный ожидаемый вывод, либо обязательные подстроки в выводе,
либо обязательные конструкции в коде (`codeContains: ["for", "range"]` — чтобы задачу
на цикл нельзя было решить копипастой четырёх `print`).

SQL (`SqlCheck`): сравнение строк результата (с опцией `orderMatters` для `ORDER BY`),
либо контрольный запрос после `INSERT`/`UPDATE`/`DELETE` (`checkQuery` + `checkRows`),
либо обязательные ключевые слова (`codeContains: ["update", "set", "where"]`).

### Геймификация

XP за каждую задачу и викторину (10–35), 6 уровней (🥚 Новичок → 🐉 Легенда кода),
награда за каждый пройденный урок и за весь трек. XP за одно задание начисляется
**один раз** — повторное решение не накручивает опыт. Подсказки открываются по одной,
эталонное решение — только после 3 неудачных попыток.

Прогресс лежит в `localStorage` под ключом `memora-coding-progress-v1` и читается через
`useSyncExternalStore`, поэтому счётчик XP в шапке и прогресс-бары обновляются
одновременно во всех виджетах страницы.

## Как добавить урок или задачу

Урок — это объект в массиве `lessons` соответствующего трека. Минимальный пример задачи:

```ts
{
  kind: "py-task",
  id: "z1",
  title: "Название задачи",
  story: ["Игровое условие. Можно `код в бэктиках`."],
  starterCode: "# подсказка-заготовка\n",
  check: { expectedOutput: "42", codeContains: ["*"] },
  hints: ["Первая подсказка", "Вторая — конкретнее"],
  solution: "print(6 * 7)",
  xp: 20,
}
```

Для SQL-урока таблицы задаются один раз в `lesson.seedSql` и доступны всем задачам урока.

**После добавления обязательно проверьте, что эталонное решение проходит собственный
чекер** — иначе задача окажется нерешаемой. Тест из раздела ниже делает это автоматически.

## Тестирование

Раздел проверялся в реальном Chromium (Playwright) на собранной production-сборке:

- 22 сценария UI: навигация, начисление и неповторное начисление XP, награды,
  разблокировка уроков, подсказки, решение после 3 неудач, 404 на несуществующий урок,
  прерывание бесконечного цикла и восстановление песочницы после него,
  пересоздание базы после `DROP TABLE`, отклонение `UPDATE` без `WHERE`;
- **36/36 эталонных решений** проходят свой чекер (каждая задача решаема);
- **18/18 викторин** засчитываются при выборе правильных вариантов.

Идея прогона всех решений: собрать данные курса в CJS (`npx esbuild src/data/coding/index.ts
--bundle --format=cjs --platform=node`), затем для каждой задачи подставить `solution`
в редактор и убедиться, что появился баннер «Задача решена!».

## Что дальше (Фаза 2, необязательно)

Спецификация `subject-packs-spec.md` позволяет подключить курс к ядру повторений:
добавить subject-pack `code` в Rust-бэкенде, сохранять решённые задачи как
`course_exercise_reviews` (FSRS) и показывать прогресс в семейном табло.
Формат задач уже совместим по смыслу: `rule.skill` ↔ навык, `rule.trap` ↔ типичная ошибка
(например, «счёт списков с нуля» или «`=` вместо `==`»).
