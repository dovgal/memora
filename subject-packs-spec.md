# Memora — Subject Packs: спецификация и план Фазы 1

> Цель: превратить Memora из «движка для французского» в мультипредметную платформу
> (языки EN/DE/ES + математика/физика/химия/история) **без поломки французского**.
> Принцип: инвариантное ядро + подключаемые «предметные паки». Все изменения обратносовместимы.
> Пилот этого пакета — **английский** (максимум переиспользования, проверка языковой обобщённости).

---

## 0. Что уже есть (не трогаем)

- **Ядро повторения:** `course_exercise_reviews` (FSRS), `course_review_logs` (streak/аналитика) — **предметно-нейтральны**, ключи `course_id/unit_id/exercise_id`. Менять не нужно.
- **Формат контента:** `custom_courses` (есть `language`, `level`), `custom_course_units` (`vocabulary`, `exercises` как JSONB в формате edito-a1).
- **AI-конвейер** (`ai.rs`, Ollama Cloud): `generate_course_unit`, `generate_exercises`, `grade_answer`, `explain_exercise`, `generate_practice`, `converse`, `regenerate_variant`.
- **Анти-повтор/варианты:** `course_exercise_variants` (`rule_key`, `format`, `payload`).
- **Голос:** Inworld TTS + `tts_cache`.

Ключевая опора для обобщения, которая **уже** есть в формате упражнения: `rule.skill` и `rule.trap`.
Для STEM «ловушка» = misconception, поэтому это золото переносится напрямую.

## 1. Модель «предметного пака»

Пак — это конфиг **в коде** (не в БД на старте). Он описывает всё предметно-специфичное:

```
SubjectPack {
  id:                 "language-fr" | "language-en" | "math" | "physics" | "chemistry" | "history"
  display_name:       "Français" | "English" | ...
  level_scheme:       LevelScheme        // как трактовать course.level
  allowed_types:      [ExerciseType]     // какие типы упражнений разрешены
  generation_prompt:  PromptTemplate     // "методист по предмету X"
  default_validation: Map<ExerciseType, ValidationStrategy>
  tts_voice:          TtsVoice           // голос(а) Inworld для этого пака
}

TtsVoice {
  default: String                        // имя голоса Inworld (для языков — нативного)
  roles:   Option<Map<Role, String>>     // опц. ролевые голоса: coach / example / dialogue
                                         // если roles = None → везде используется default
}
```

> Голос выбирается **по паку** (= по языку курса), а не один на всё приложение —
> иначе французский голос будет читать английский текст с неверной фонетикой.
> Один диктор → задать только `default`. Разные голоса под роли → заполнить `roles`.

- `level_scheme`:
  - `Cefr` — для языков (A1…C2). Текущее поведение французского.
  - `Grade` — класс/программа (например, «7 класс», «школьная физика»).
  - `ConceptGraph` — уровень определяется освоенностью пререквизитов (для STEM позже).
- Реестр: `fn pack_for(subject: &str, language: Option<&str>) -> &'static SubjectPack`.
  - Встроенные курсы по id: `"edito-a1" -> "language-fr"`.
  - Пользовательские: `custom_courses.subject` (+ `language` для языков) -> pack.

**Первый пак `language-fr` обязан 1:1 повторять нынешнее поведение** — это и есть тест на обратную совместимость.

## 2. Обобщённая схема упражнения (надмножество текущей)

Все нынешние поля французского остаются и продолжают работать. Добавляется **типизированный ответ** и `rule.level`.

```jsonc
{
  "id": "verbes-prep-souvenir",
  "type": "error-hunt",            // открытый набор (см. §3), не enum из двух значений
  "title": "…",
  "prompt": "…",                   // обобщённая формулировка задания (для не-error-hunt)

  // --- НОВОЕ: типизированный ответ (канонический способ проверки) ---
  "answer": {
    "kind": "error-hunt",          // = стратегия проверки (см. §3)
    "errorIndex": 3,               // поля зависят от kind
    "correction": "de"
  },

  // --- СТАРЫЕ поля error-hunt остаются для совместимости рендерера ---
  "sentence": "Je me souviens à mon enfance.",
  "errorIndex": 3,
  "correction": "de",

  "explanation": "…",
  "rule": {
    "skill": "verb-government",
    "point": "se souvenir de qqch",
    "trap":  "se souvenir à / смешение с se rappeler",
    "examplesCorrect": ["…"],
    "level": "B1",                 // НОВОЕ имя; "cefr" оставить как алиас при чтении
    "cefr":  "B1"                  // сохраняем, чтобы старый контент не падал
  },
  "variantPolicy": { "regenerateOnRepeat": true, "format": "error-hunt", "avoidLastN": 6 }
}
```

Правило миграции данных: **никаких разрушительных изменений**. Старые упражнения без `answer`
трактуются по `type`+`errorIndex`/`correction` (как сейчас). Новые — по `answer.kind`.
`rule.level` читается с фолбэком на `rule.cefr`.

## 3. Типы упражнений → стратегия проверки (самое важное)

Главный риск мультипредметности — проверка ответа. LLM **нельзя** доверять арифметику,
алгебру и баланс реакций. Поэтому проверка — это стратегия по `answer.kind`:

| answer.kind     | Стратегия проверки                                  | Где считается        | Предметы                |
|-----------------|-----------------------------------------------------|----------------------|-------------------------|
| `error-hunt`    | детерминированно по `errorIndex`/`correction`       | сервер, без LLM      | языки (текущее FR)      |
| `mcq`           | сравнение с id правильного варианта                  | сервер, без LLM      | любой                   |
| `cloze` / `fill`| нормализованное сравнение (+ опц. LLM на синонимы)   | сервер (+LLM)        | языки                   |
| `short-text`    | семантическая оценка (`grade_answer`)               | LLM                  | языки, гуманитарные     |
| `ordering`      | сравнение последовательности                        | сервер, без LLM      | история (хронология)    |
| `numeric`       | сравнение с допуском + приведение единиц            | сервер, **НЕ LLM**   | физика, химия           |
| `symbolic`      | CAS-эквивалентность (SymPy-сервис)                  | внешний, **НЕ LLM**  | математика              |
| `reaction`      | детерминированная проверка баланса уравнения        | сервер, **НЕ LLM**   | химия                   |
| `open-rubric`   | грунтованная оценка по рубрике (LLM + источник)     | LLM + RAG            | история, эссе           |

**Для пилота-английского новые валидаторы не нужны:** он использует
`error-hunt`, `mcq`, `cloze`, `short-text`, `converse` — все стратегии уже есть.
`numeric`/`symbolic`/`reaction` появляются только на фазе STEM.

## 5. Пилот: пак `language-en`

```
id:            "language-en"
display_name:  "English"
level_scheme:  Cefr (A1..C2)
allowed_types: [error-hunt, mcq, cloze, short-text, converse]
generation_prompt: «Ты — методист по английскому (CEFR {level}). …» (калька с FR-промпта)
default_validation:
  error-hunt -> deterministic
  mcq        -> deterministic
  cloze      -> deterministic(+synonyms LLM)
  short-text -> llm-judge (grade_answer)
  converse   -> llm (converse)
tts_voice:
  default: "<английский голос Inworld>"   // подтверждено: EN-голос в Inworld есть
  roles:   None                           // на старте один диктор; ролевые голоса — позже
```

> `language-fr` получает свой `tts_voice.default` = текущий французский голос из `audio.rs`
> (вынести хардкод голоса в пак, не менять звучание французского).

Проверка успеха пилота: создать английский курс, сгенерировать юнит, пройти в коуч-режиме
(FSRS-повторение работает без изменений), озвучить через Inworld (нужен EN-голос).
**Французский при этом проходит все прежние сценарии без регрессий.**

>    и новый (по `answer.kind`); для пилота достаточно уже существующих типов.
> 7. **Озвучка по паку** (`handlers/audio.rs`): вынести хардкод голоса в пак (`tts_voice.default`);
>    `synthesize_tts` выбирает голос по `subject`/`language` курса. Модель `inworld-tts-1.5-max`
>    пока оставить. `language-fr.tts_voice.default` = нынешний французский голос (звучание FR не меняется).
> 8. **Ключ кэша TTS** (`tts_cache`): включить в ключ **голос/язык**, а не только текст —

>    Существующие записи французского кэша не должны инвалидироваться без причины.

> **Обязательно — тесты обратной совместимости:** существующий французский курс (`edito-a1`)
> рендерится, генерируется и грейдится точно как раньше; **французская озвучка звучит тем же голосом
> и берётся из кэша без регенерации**; миграция накатывается на копии прод-схемы
> без потери данных; `course_exercise_reviews` не затронута.
>
> Работай слайсами размером с PR: миграция+реестр -> DTO -> handlers -> web. Каждый слайс — отдельная ветка.

## 7. Модели

**Исполнитель в Claude Code (пишет код):**
- **Opus** — на кросс-срезовую сложную работу: обобщение схемы, миграции, абстракция паков,
  стратегия проверки. Ошибка в Rust/миграциях дорогая.
- **Sonnet** (через поле `model` у сабагента) — на объём: контент, CRUD, тесты. Hard → Opus, bulk → Sonnet.

**Движок Memora (генерация/проверка/коуч, Ollama Cloud):**
- Рабочая лошадка — текущий `gpt-oss:120b`. На трудные пути (грунтованная генерация, история,
  разбор источника) пробовать модель посильнее из актуального каталога Ollama Cloud
  (крупные DeepSeek/Qwen; имена и «уровни нагрузки» сверять на их странице — тяжёлые жгут квоту).
- Везде включить **structured outputs (JSON-схему)** — убирает ошибки парсинга в генерации/проверке.
- **STEM-проверка — НЕ модель:** числа/единицы/символика/баланс реакций → детерминированные
  валидаторы / SymPy-сервис. Это снимает главный риск и делает выбор движка менее критичным.

Общий принцип: переключатель модели на агента/шаг — лёгкое (подсказки, проверка) на модель полегче,
тяжёлая генерация — фоновым воркером на сильной.
